# 專案快照範本

專案快照記下「這個 Jira 專案查過一次的結果」，下次開單時在第一段之前讀，不必每次重新摸索站台參數、Epic、標題寫法與標籤慣例。

## 放哪裡、什麼時候寫

- 位置：`~/.config/pm-toolkit/jira/{專案代號小寫}.md`（例：專案代號 `ABC` → `abc.md`）。設了 `$XDG_CONFIG_HOME` 時，放在 `$XDG_CONFIG_HOME/pm-toolkit/jira/`。
- 只放本機，不進任何 repo，也不放進 skill 目錄：快照裡有站台網址、角色對應、內部連結與真實實例。
- 第一次寫：使用者在第二段同意存快照後，在第六段回查完再寫——這時欄位 ID、標籤、標題寫法都已經實際用過一次。
- 更新：每次開單查到的事實跟快照不同，以查到的為準，並提醒使用者更新；同意後再改，並更新快照日期。
- 查不到或還沒查的欄位寫「未查」，不要留空白，也不要猜。

## 這份快照跟 `config.yaml` 的關係

`~/.config/pm-toolkit/config.yaml` 管的是「這個 repo 用哪種 tracker」：把 repo 登記成 `provider: jira` 的 profile 並帶 `project_key`，在 repo 裡跑 `pm-config.mjs show --json` 就能拿到預設的專案代號，`issue-new.mjs` 也不會在這個 repo 裡建出 `issues/` 資料夾。登記走 `init-tracker-config` skill。

快照管的是「這個 Jira 專案怎麼開單」，內容是文字，跟 repo 無關（同一個 Jira 專案可能對應好幾個 repo，或一個都沒有），所以分開放。
